# 조교 운영 가이드

수업 시작 전 계정 안내부터 시험 종료 후 성적 확인까지의 순서입니다. 관리자는 서비스의 **Admin Panel**에서 작업할 수 있습니다. 먼저 운영 담당자에게 운영·dev 주소, 관리자 계정, 수강생 명단과 시험 일정을 받아 주세요. dev는 설정·제출을 연습할 개발 환경입니다.

## 1. 학생 가입 안내

학생은 학교 Google Workspace 계정으로 인증한 뒤 첫 계정 설정 화면에서 ID·Nickname(본명)·비밀번호·학번·약관 동의를 입력해야 합니다. Workspace를 사용하지 않는 학교의 학생은 관리자에게 계정 생성을 요청해야 합니다.

이후에는 **ID 또는 이메일 + 비밀번호**로 로그인할 수 있습니다. Google 재로그인은 새 비밀번호 설정으로 이어집니다. 시험 전에 각자 계정 설정과 로그인을 완료해 보도록 안내하는 것이 좋습니다.

| 항목 | 운영 시 알아야 할 점 |
|---|---|
| ID | 로그인용 고유 값. 학생 설정 화면에서는 읽기 전용입니다. 관리자는 ID로 검색할 수 있습니다. |
| Nickname | 표시용 본명. 동명이인을 허용하므로 학번·이메일을 함께 대조해야 합니다. |
| 이메일 | Google 계정 연결과 로그인에 사용합니다. 변경이 필요하면 관리자에게 요청해야 합니다. |
| 학번 | 시험 참여 명단과 성적을 연결하는 기준입니다. |

테스트용 또는 수동 발급 계정은 관리자 **Users**에서 생성하고 학번을 입력할 수 있습니다. 계정 소유자에게 초기 비밀번호를 비공개로 전달하고 첫 로그인·필수 정보·약관 동의가 완료되는지 확인해 주세요. 가입·비밀번호 복구 흐름을 실제 학교 계정으로 검증할 때는 계정 소유자가 직접 인증해야 합니다.

### Google 계정 허용 범위

기본 설정은 모든 조직의 검증된 Workspace 계정을 허용하며 개인 Google 계정은 거부합니다. 기업 Workspace도 포함되므로 수강생만 시험에 참여하게 하려면 아래의 학번 명단을 설정해야 합니다.

학교별로 제한하려면 배포 담당자가 AWS Secrets Manager의 애플리케이션 설정 `GOOGLE_HOSTED_DOMAIN`을 변경해야 합니다. `*` 또는 빈 값은 모든 Workspace, `hanyang.ac.kr,partner.edu`는 나열한 조직만 허용합니다. 서버 기동 시 읽는 값이므로 승인된 인스턴스 교체 후 실제 로그인으로 확인해야 합니다.

### 이용 약관

관리자 **Config → Legal → Terms of Service**에서 본문을 편집할 수 있습니다. `/tos`와 학생 첫 설정 화면에 표시되는지 확인해 주세요. 이미 저장된 본문과 동의 기록은 유지되므로, 재동의가 필요한 개정이라면 대상·방법을 함께 정해야 합니다.

## 2. 문제 준비

1. [출제 가이드](../platform/CTFd/plugins/sql_challenges/AUTHORING.md)로 지문·데이터·정답·공개 채점 기준을 준비해 주세요.
2. [문제 검토 가이드](../platform/CTFd/plugins/sql_challenges/REVIEW.md)로 문제 세트를 실행해 보고 동료 조교에게 지문을 검토받는 것이 좋습니다.
3. dev에서 [제출 점검](../platform/CTFd/plugins/sql_challenges/SUBMISSION_REVIEW.md)을 진행해 Test·Submit·성적 반영을 확인해야 합니다.

문제별 마감은 SQL 문제의 **Deadline (KST)**에 설정합니다. 전체 시험 시작·종료·일시 중지 설정도 함께 확인해야 합니다.

## 3. 시험 참여·브라우저·세션 설정

**위치:** 관리자 **Plugins → Exam Mode** (`/admin/exam_mode/`). 세 스위치의 기본값은 off이며 각 규칙을 별도로 관리합니다.

| 설정 | 준비·저장 | 적용 결과 |
|---|---|---|
| Enable Exam Mode | Allowed Student IDs에 학번을 한 줄에 하나씩 넣고 위쪽 **Save & Apply** | 해당 학번의 학생만 접근할 수 있습니다. 비어 있지 않은 명단과 `Student ID Number` 사용자 필드가 필요합니다. |
| Allow the exam browser only | User-Agent marker를 확인한 뒤 아래쪽 **Save** | 지정 브라우저의 학생 접근을 허용합니다. 기본 marker는 `Trustlockbrowser`이며 브라우저 식별 문자열의 대소문자 무관 부분 일치로 검사합니다. Google 로그인 버튼은 숨겨집니다. |
| Allow only one session per student | 아래쪽 **Save** | 새 학생 로그인이 이전 세션을 종료합니다. |

관리자는 일반 브라우저·여러 세션을 사용할 수 있고 서버 상태 검사도 유지됩니다. 규칙이 켜져 있으면 관리자 배너에서 확인할 수 있습니다.

**시험 전:** 학생의 계정 설정·비밀번호 준비가 끝났는지 확인한 뒤 규칙을 켜야 합니다. 테스트 학생으로 명단 포함·제외, 앞자리 0 학번, 시험 브라우저와 두 번째 로그인을 점검하는 것이 좋습니다.

**시험 후:** 세 스위치를 각각 원하는 상태로 바꾸고 명단 폼·세션 규칙 폼을 각각 저장해 주세요. 설정은 로그인 중인 학생에게도 적용되므로 변경 시점을 수업 담당자와 맞춰야 합니다.

## 4. 서버 용량 확보

시험 시작에 요청이 몰리기 전에 서버를 확보하려면 배포 담당자에게 **시험 날짜·시각·동시 접속 인원·문제 규모**를 전달해야 합니다. 담당자는 [AWS 운영 가이드](../IaC/README.md)의 `exam_windows`로 미리 확장할 수 있습니다.

서버 용량 예약은 Terraform에서, 학생 접근 규칙은 Exam Mode에서, 제출 기간은 전체 시험 시간·문제별 Deadline에서 각각 관리해야 합니다.

## 5. 시험 중 문의 대응

| 문의 | 먼저 확인할 것 |
|---|---|
| 로그인 실패 | ID 또는 이메일 사용 여부, 비밀번호, 필수 계정 설정 완료 여부 |
| 접근 거부 | 허용 학번 명단, 실제 학생 계정의 학번, 시험 브라우저 설정 |
| 갑자기 로그아웃 | 단일 세션 설정과 다른 기기에서의 로그인 여부 |
| SQL 판정 불가 | 관리자 Test의 정답 실행·채점 기준, 여러 문제에서 반복되는지 |
| 제출 횟수 제한 | 문제의 Max Attempts와 저장된 오답 기록 |
| 마감 후 제출 요청 | 서버의 접수 시각·제출 기록·장애 발생 시각 |

문제가 계속되면 서비스 주소, 문제 번호, 발생 시각, 화면 메시지와 재현 순서를 개발 담당자에게 전달해 주세요. 비밀번호·토큰은 전달 기록에 넣지 않아야 합니다. 실제 학생 SQL·개인정보가 필요하면 수업의 비공개 경로를 사용해야 합니다.

## 6. 종료 후 성적과 기록

[성적 내보내기 가이드](../platform/CTFd/plugins/submission_export/README.md)에 따라 CSV를 내려받고 학번 명단·문제 배점과 대조해 주세요. 테스트 계정과 다른 수업 계정을 걸러내고, 성적 확정 시점의 파일을 보관하는 것이 좋습니다.

Test 실행·로그인은 서버 로그로, 붙여넣기·탭 이동 등은 브라우저 이벤트로 기록됩니다. 부정행위 의심 사례는 제출 SQL·서버 기록·브라우저 이벤트를 함께 검토해야 합니다. 브라우저 식별 문자열과 이벤트는 사용자가 조작할 수 있다는 점을 판단에 반영해야 합니다.

다음 조교에게는 서비스·dev 주소, 접근 권한을 받는 방법, 사용한 문제 세트, 시험 설정, 성적 대조 방법과 남은 확인 항목을 남겨 주세요. 비밀번호·키는 정해진 비밀 관리 경로로 인계해야 합니다.
