# SQL 문제 기능 안내

이 디렉터리는 SQL 문제 유형, 채점 서버와 조교용 가이드를 담고 있습니다. 웹 서비스는 CTFd가 계정·문제·점수를 관리하고, Go로 만든 judge가 MySQL 8.4에서 SQL을 실행해 판정합니다.

| 업무 | 가이드 |

| 처음 문제 만들기 | [출제 가이드](AUTHORING.md) — 화면 항목과 완성된 예제 |
| 문제 세트 일괄 검사 | [문제 검토 가이드](REVIEW.md) — 도구 준비, 실행, 보고서 해석 |
| 학생의 실행·제출·점수 확인 | [제출 점검 가이드](SUBMISSION_REVIEW.md) — 브라우저 점검 순서 |
| 계정·시험 규칙 운영 | [조교 운영 가이드](../../../../docs/TA_OPERATIONS.md) |

## 채점 흐름

1. CTFd가 로그인, 문제 접근 권한, 제출 기간과 시도 횟수를 확인합니다.
2. judge가 임시 DB에 문제 데이터를 준비합니다.
3. 정답과 학생 SQL을 같은 데이터에 대한 각각의 읽기 전용 연결에서 실행합니다.
4. 공개된 정렬·표시 형식 규칙에 따라 결과를 비교합니다.
5. CTFd가 판정을 표시하고 Submit의 결과를 저장합니다. Test는 실행 확인용입니다.

초기화 SQL과 정답 SQL은 관리자만 조회할 수 있으므로, 학생에게 필요한 테이블 설명은 출제자가 지문에 적어야 합니다.

## 개발자가 볼 파일

| 파일 | 역할 |
|---|---|
| `__init__.py` | 문제 생성·수정, 관리자 SQL 실행, judge 연결 |
| `policy.py` | 공개 채점 기준 검증과 안내문 |
| `submissions.py` | 접수·마감·동시 실행·결과 저장 |
| `sql_judge_server.go` | MySQL 연결, 임시 DB·계정, 실행 제한 |
| `grading_results.go` | 숫자·NULL·중복·정렬 결과 비교 |
| `assets/` | 관리자 SQL 문제 폼 |
| `migrations/` | SQL 문제 저장 구조의 버전 변경 |

judge의 HTTP 인터페이스와 자동 테스트 실행법은 개발 가이드에서 이어서 설명합니다. 운영 중인 서비스의 현재 버전·기동 상태는 배포 기록에서 확인해야 합니다.
