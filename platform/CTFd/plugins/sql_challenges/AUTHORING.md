# SQL 문제 출제 가이드

관리자 화면에서 문제를 만들고 학생에게 공개하기까지의 순서입니다. 처음이라면 개발 환경(dev)에서 아래 예제 문제를 만들어 보는 것이 좋습니다. 서비스 주소와 관리자 계정은 운영 담당자에게 요청해야 합니다.

## 1. 문제에 필요한 자료 준비

| 자료 | 담아야 할 내용 |
|---|---|
| 지문(Description) | 학생이 조회할 내용, 테이블·열 설명, 출력 열 순서, 정렬·반올림·표시 형식 요구, 예시 결과 |
| 초기화 SQL(Initialization Query, init) | 테이블을 만들고 데이터를 넣는 `CREATE TABLE`, `INSERT` 등 |
| 정답 SQL(Solution Query) | 지문을 만족하는 결과를 반환하는 단일 `SELECT` |

초기화 SQL과 정답 SQL은 관리자만 조회할 수 있습니다. 학생이 필요한 테이블 구조와 열 설명은 **지문에 직접 적어야 합니다.**

채점은 MySQL 8.4를 사용합니다. 매 요청마다 새 임시 DB에 초기화 SQL을 실행한 뒤 정답과 학생 SQL이 같은 데이터를 조회합니다. 두 쿼리는 각각의 읽기 전용 연결을 사용하며, 실행을 마치면 임시 DB를 정리합니다.

## 2. 예제 문제 만들기

관리자로 로그인해 **Challenges → Create Challenge**에서 문제 유형 `sql`을 선택해 주세요.

| 화면 항목 | 예제 입력 | 설명 |
|---|---|---|
| Name | 점검용 상품 조회 | 문제 제목 |
| Category | 조교 연습 | 목록에서 묶을 분류 |
| Value | 10 | 정답 점수 |
| State | Hidden | 작성 중에는 숨김으로 저장하고, 검토 후 Visible로 바꿉니다. |
| Max Attempts | 0 | 오답 횟수 제한. `0`은 무제한입니다. |
| Deadline (KST) | 비워 둠 | 문제별 제출 마감. 설정할 때는 한국 시각을 입력해야 합니다. |

### Description에 넣을 지문

> `products`에는 상품 번호 `id`(INT), 분류 `category`(VARCHAR), 가격 `price`(DECIMAL)가 있습니다.
>
> 가격이 2.50 이상인 상품의 번호와 가격을 순서대로 출력하세요. 가격 내림차순으로 정렬하고, 가격이 같으면 상품 번호 오름차순으로 정렬하세요.

예상 결과:

| id | price |
|---|---|
| 2 | 2.50 |
| 3 | 2.50 |

### Initialization Query에 넣을 SQL

```sql
CREATE TABLE products (
    id INT PRIMARY KEY,
    category VARCHAR(10),
    price DECIMAL(10, 2)
);
INSERT INTO products VALUES
    (1, 'A', 1.00),
    (2, 'A', 2.50),
    (3, 'B', 2.50);
```

### Solution Query에 넣을 SQL

```sql
SELECT id, price
FROM products
WHERE price >= 2.50
ORDER BY price DESC, id ASC;
```

**정렬 기준**에는 `2 desc, 1 asc`, **표시 형식까지 평가하는 열 번호**에는 빈 값을 넣어 주세요. 이 지문은 가격의 값과 정렬을 요구합니다. 예시의 `2.50`을 `2.5`로 출력해도 같은 숫자 값으로 인정됩니다.

**Test SQL Queries**로 초기화·정답 SQL의 실행 결과를 확인한 뒤 **Create** 또는 **Update**로 저장해 주세요. 이 버튼은 관리자 SQL의 실행을 확인하는 기능입니다. 다른 풀이가 정답으로 인정되는지는 저장 후 학생 문제 화면의 **Test**에서 확인할 수 있습니다.

학생 계정으로 점검할 때는 **dev의 예제 문제를 Visible로 바꿔야** 열 수 있습니다. 점검 후에는 다시 Hidden으로 돌려 주세요. 실제 수업 문제는 검토가 끝난 뒤 공개하는 것이 좋습니다.

## 3. 지문과 채점 설정 맞추기

관리자 화면에서 저장한 기준은 학생 문제 화면에도 표시됩니다. 지문과 설정이 일치해야 합니다.

| 기준 | 설정 방법 | 예시 |
|---|---|---|
| 출력 열 | 결과 열의 위치로 비교합니다. 별칭은 자유롭게 사용할 수 있습니다. | `id, price`와 `price, id`는 다른 결과입니다. |
| 행 순서 | 순서 무관이면 정렬 기준을 비워 두고 저장합니다. 정렬 요구가 있으면 결과 열 번호와 `asc`·`desc`를 입력해야 합니다. 번호는 1부터 시작합니다. | `2 desc, 1 asc` |
| 중복 | 같은 행의 개수까지 비교합니다. | 같은 가격의 상품 2개가 있다면 `DISTINCT`로 한 행만 반환하는 답은 오답입니다. |
| 숫자 | 정확한 값으로 비교합니다. 큰 정수·DECIMAL도 값 그대로 비교합니다. | `1 = 1.00`, `1.234 ≠ 1.23` |
| NULL·자료형 | SQL NULL, 문자열, 숫자를 구별합니다. | `NULL`, `'NULL'`, `''`는 각각 다른 값입니다. 숫자 `1`과 문자열 `'1'`도 구별합니다. |
| 표시 형식 | 지문에서 표현까지 요구한 열을 지정해야 합니다. | 항상 소수 두 자리라면 해당 열 번호를 표시 형식 평가에 추가합니다. |
| 문자열·날짜 | 출력 값의 공백·대소문자까지 비교합니다. | `'A'`와 `'a'`는 서로 다릅니다. |

### 반올림한 값과 소수 자릿수 표시

“소수 둘째 자리로 반올림한 값”을 요구하려면 지문에 기준을 적고 정답 SQL에 `ROUND`를 사용할 수 있습니다. “항상 소수 두 자리로 표시”까지 요구한다면 해당 열을 표시 형식 평가에 추가하고, 정답 출력도 그 형식으로 맞춰야 합니다. 학생의 결과는 제출한 SQL이 출력한 값으로 평가합니다.

### 정렬 값이 같은 행

MySQL이 같은 정렬 값으로 판단한 행끼리는 순서가 자유롭습니다. 예를 들어 가격 내림차순만 요구했다면 가격이 같은 상품의 번호 순서는 자유롭게 허용됩니다. 번호 순서까지 요구하려면 지문과 정렬 기준에 함께 넣어야 합니다.

`LIMIT` 경계에 동률이 있으면 선택되는 행 자체가 달라질 수 있습니다. 이때는 어느 행을 선택해야 하는지 지문·정답에 기준을 명확히 적어야 합니다. 정렬 기준은 결과에 포함된 열로 지정할 수 있습니다.

### 이전에 만든 문제

채점 기준이 미확정인 문제는 관리자 화면에 경고가 표시되고 학생에게는 판정 불가로 안내됩니다. 지문을 확인한 뒤 정렬·표시 형식 필드를 저장해야 사용할 수 있습니다. 두 필드를 비운 채 저장하면 “순서 무관·숫자 값 비교” 기준이 확정됩니다.

## 4. 사용할 수 있는 SQL과 실행 한도

| 항목 | 기준 |
|---|---|
| MySQL | 8.4. 기본 정렬 규칙은 `utf8mb4_0900_ai_ci`이며 SQL 연산은 열의 collation을 따릅니다. 최종 출력 문자열은 위 표처럼 비교합니다. |
| 정답·학생 SQL | 단일 SELECT. 읽기 전용 권한으로 실행합니다. |
| 시간 | 초기화+정답 검증 2.5초, 학생 쿼리 2.5초, 요청 전체 8초 |
| 크기 | 요청 본문 1MiB, 결과 최대 1,000행 또는 4MiB |
| 테이블 이름 | 대소문자를 구별하지 않습니다. |

MySQL Workbench·mysqldump의 일반적인 스크립트를 사용할 수 있습니다. `CREATE SCHEMA`, `DROP SCHEMA`, `USE`와 스키마를 붙인 테이블 이름은 채점용 임시 DB로 연결됩니다. 하나의 스키마를 사용하는 문제로 준비해 주세요.

- 초기화 SQL의 `SET SQL_MODE`는 정답·학생 연결에도 적용됩니다. 생략하면 MySQL 8 기본 모드(엄격 모드, `ONLY_FULL_GROUP_BY` 포함)를 사용합니다. `TRADITIONAL`을 지정하면 GROUP BY 허용 범위가 달라질 수 있으므로 의도한 모드인지 확인해야 합니다.
- 문장은 세미콜론으로 나눕니다. 문자열 안의 세미콜론, `DELIMITER`, 프로시저·함수·트리거의 복합 본문은 이 실행 방식에 맞지 않습니다. 초기화 자료를 단순한 테이블 생성·데이터 입력으로 준비하는 것이 좋습니다.
- 트랜잭션을 직접 시작했다면 초기화 SQL 끝에서 `COMMIT`해야 합니다.
- `SET GLOBAL`, 사용자·권한 변경, 파일 읽기·출력은 제한됩니다. `SLEEP`, `BENCHMARK`, 이름 기반 잠금 함수와 실행 시간 제한을 덮어쓰는 힌트도 제한됩니다. 일반 열 이름이나 문자열 안의 단어는 사용할 수 있습니다.
- 여러 테이블에 같은 열 이름이 있다면 `GROUP BY products.id`처럼 소속을 명시해야 합니다. 정답의 `RAND()`·`UUID()` 등 실행마다 달라지는 값은 피하는 것이 좋습니다.

## 5. 게시 전 확인

1. dev의 점검용 문제를 Visible로 바꾸고 학생 화면에서 지문·테이블 설명·공개 채점 기준이 맞는지 확인해 주세요.
2. 정답과 다른 풀이의 정답, 조건이 틀린 답을 Test로 실행해 보세요. 학생 Test와 Submit의 차이는 [제출 점검 가이드](SUBMISSION_REVIEW.md)에서 확인할 수 있습니다.
3. 동료 조교에게 지문·초기화 데이터·정답·예시 결과를 함께 검토받는 것이 좋습니다.
4. [모범답안 일괄 채점](REVIEW.md)으로 각 문제의 모범답안이 정상적으로 정답 처리되는지 확인해 주세요.
5. 검토가 끝나면 State를 Visible로 바꾸고 전체 시험 시간·문제 마감·접근 규칙을 확인해야 합니다. 작성 중인 문제는 Hidden으로 유지해 주세요.

문제 오류로 판정 불가가 발생하면 학생의 오답 횟수는 보존됩니다. 학생 SQL의 오류·한도 위반·결과 불일치는 오답으로 처리됩니다. 문의를 받았을 때의 확인 순서는 [제출 점검 가이드](SUBMISSION_REVIEW.md)를 참고해 주세요.
