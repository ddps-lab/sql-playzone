# SQL 문제 출제 가이드

문제를 만들기 전에 한 번 읽어 주세요. 이 플랫폼은 여러분이 로컬 MySQL에서 쓰던 스크립트를 대부분 그대로 받지만, 채점기가 실행하는 방식이 로컬과 달라서 알아 두어야 할 점이 있습니다. 문제를 저장한 뒤에는 반드시 관리자 화면의 **Test**로 init과 정답을 한 번 실행해 보세요.

## 채점기가 실행하는 방식

| 항목 | 동작 |
|---|---|
| 실행 단위 | 제출마다 정답 쿼리와 학생 쿼리를 **하나의 새 임시 데이터베이스**에서 서로 다른 읽기 전용 연결로 실행하고 바로 삭제합니다. |
| init | 문제의 init SQL을 매번 처음부터 실행합니다. 이전 실행의 데이터는 남지 않습니다. |
| 계정 | init은 그 임시 DB에 모든 권한을 가진 계정으로, 정답·학생 쿼리는 **SELECT만** 가능한 계정으로 실행합니다. |
| 세션 | init과 채점 쿼리는 다른 연결이지만, init에서 `SET SQL_MODE=...`로 바꾼 값은 채점 쿼리에도 그대로 적용됩니다. 로컬에서 스크립트를 돌린 뒤 같은 창에서 쿼리하는 것과 같습니다. |
| 시간 | init + 정답 검증에 2.5초, 학생 쿼리에 별도 2.5초, 요청 전체 8초. 학생 쿼리에 대해 확인된 실행 한도 위반은 오답이며, 준비·통신·요청 전체의 시간 초과는 판정 불가로 처리합니다. |
| 크기 | 요청 본문 1MiB, 결과 1,000행 또는 4MiB. |
| MySQL | 8.4, 기본 `utf8mb4_0900_ai_ci`(SQL 연산·정렬 동률은 해당 열의 collation 사용; 최종 문자열 값은 대소문자·공백 구별), 테이블명 대소문자 구분 없음(Windows·macOS 로컬과 동일). |

## init SQL

**그대로 붙여도 되는 것**

- MySQL Workbench나 mysqldump로 내보낸 스크립트. `DROP SCHEMA IF EXISTS kbo;`, `CREATE SCHEMA kbo;`, `USE kbo;`는 실행하지 않고 임시 DB로 매핑합니다. `kbo.PLAYER`처럼 스키마를 붙인 이름도 임시 DB로 바뀝니다.
- `SET @OLD_SQL_MODE=@@SQL_MODE, SQL_MODE='TRADITIONAL';` 같은 세션 설정, `/*!40101 SET ... */` 헤더, `LOCK TABLES`, `SET autocommit=0; ... COMMIT;`.
- 문장 앞의 `-- 주석`, `/* 주석 */`, `-----` 구분선.

**안 되는 것**

- 스키마 두 개 이상을 만들어 조인하는 스크립트. 모두 같은 임시 DB로 합쳐지므로 같은 이름의 테이블이 있으면 충돌합니다. 스키마는 하나만 쓰세요.
- `DELIMITER`, 프로시저·함수·트리거의 `BEGIN ... END` 본문, 문자열 값 안의 세미콜론. 문장은 단순히 `;`로 나뉩니다.
- 문장 **중간**에 끼어 있는 `-----` 줄. MySQL은 `--` 뒤에 공백이 없으면 주석으로 보지 않습니다.
- `FLUSH`, `SET GLOBAL`, 계정·권한 문장.
- `START TRANSACTION`을 열고 `COMMIT` 없이 끝나는 스크립트. init 연결이 닫히면서 롤백됩니다.

**권장**

- `CREATE SCHEMA`의 문자셋 옵션은 무시됩니다. 문자열 정렬이 중요하면 열에 `COLLATE`를 직접 지정하세요.
- `SET SQL_MODE`를 쓰면 그 모드가 학생 쿼리에도 적용됩니다. 예를 들어 `'TRADITIONAL'`은 `ONLY_FULL_GROUP_BY`를 끄므로 `GROUP BY`에 없는 열을 SELECT해도 통과합니다. SET이 없으면 MySQL 8 기본값(strict, `ONLY_FULL_GROUP_BY` 켜짐)입니다. 어느 쪽을 의도하는지 정하고 명시하세요.
- 데이터가 크면 Test에서 걸리는 시간을 확인하세요. 250KB(INSERT 수천 행) init이 운영 인스턴스에서 약 0.7초입니다.

## 정답 SQL

- **단일 SELECT 문**만 가능합니다. 여러 문장, DML, DDL, `USE`는 학생 쿼리와 마찬가지로 거부됩니다.
- 관리자 화면의 **정렬 기준**과 **표시 형식까지 평가하는 열**이 채점 규약입니다. 저장한 규약은 학생 문제 화면과 상세 API에도 같은 내용으로 공개됩니다. 지문과 설정이 일치해야 합니다. 결과 열 번호는 1부터 시작하며 별칭은 평가하지 않습니다.
- 기본값은 **행 순서 무관, 중복 수 포함**입니다. 지문에 정렬 요구가 있을 때만 `1 asc, 2 desc`처럼 결과 열의 순서를 설정하세요. MySQL이 정렬 값을 비교해 같은 것으로 판단한 행끼리는 순서가 자유롭습니다. 유일한 보조 정렬 기준을 임의로 추가할 필요가 없습니다.
- 정렬 기준은 결과에 포함된 열로 지정합니다. `LIMIT` 경계에 동률이 있어 선택되는 행 자체가 달라질 수 있는 문제는 지문·정답에서 선택 기준을 명확히 하세요. 실행할 때마다 답이 달라지는 `RAND()`, `UUID()` 등은 정답 결과에 사용하지 마세요. init에서 한 번 생성한 데이터는 두 쿼리가 함께 봅니다.
- **숫자는 정확한 값으로 비교합니다.** `1`, `1.00`은 같고 `1.234`, `1.23`은 다릅니다. 임의 오차 허용이나 자동 반올림은 없습니다. 큰 정수와 DECIMAL을 부동소수점으로 변환하지 않습니다. 숫자와 문자열 `'1'`은 기본적으로 다릅니다.
- 반올림한 **값**을 요구하면 지문과 정답에 `ROUND` 등을 적용하세요. 끝자리 0까지 포함해 소수 두 자리 **표시**를 요구한다면 지문에 명시하고 해당 열 번호를 표시 형식 평가에 추가하세요. 이 열에서는 정답 결과와 표시 문자열이 같아야 합니다. 채점기가 학생 값을 대신 반올림하지 않습니다.
- SQL `NULL`은 문자열 `'NULL'` 및 빈 문자열과 다릅니다. 화면에서도 SQL NULL을 별도로 표시합니다. 날짜·시각과 일반 문자열은 출력 값을 그대로 비교하며 공백·대소문자를 자동 교정하지 않습니다.
- 기존 문제의 비교 규약은 자동 추측하지 않습니다. 업그레이드 후 규약이 없는 문제는 **판정 불가·횟수 차감 없음**입니다. 관리자 화면에서 지문을 확인하고 기준을 저장한 뒤 사용하세요. 기존 원본 데이터와 과거 점수는 자동 수정하지 않습니다.
- 두 테이블에 같은 이름의 열이 있으면 `GROUP BY TEAM.TEAM_ID`처럼 테이블을 붙이세요. `GROUP BY TEAM_ID`는 MySQL이 ambiguous 오류를 냅니다.
- 상관 서브쿼리 안의 `GROUP BY`처럼 느린 형태는 피하세요. 정답 실행 시간이 곧 채점 시간이고 2.5초를 넘으면 문제 자체가 채점 불가가 됩니다.
- 지문의 **예시 출력은 Test 결과를 복사**해서 넣으세요. 그래야 학생이 보는 표현과 일치합니다.

## 실행 제한

임시 DB의 MySQL 권한이 격리를 담당합니다. 학생 쿼리는 읽기 전용이며 파일 출력·계정 권한 변경·시스템 계정 정보 접근을 허용하지 않습니다. `SLEEP`, `BENCHMARK`, `LOAD_FILE`, 이름 기반 잠금 함수, 실행 시간 제한을 덮어쓰는 `MAX_EXECUTION_TIME` 힌트도 제한합니다.

문자열·일반 주석 및 식별자 내부의 단어로 차단하지 않습니다. `profile`, `execution_date`, `system_id` 같은 열 이름과 문자열 `'SLEEP(5)'`는 사용할 수 있습니다. 실행되는 버전 주석과 optimizer hint는 검사합니다. 이 보조 검사는 SQL 문법 판별기를 대신하지 않으며 실제 문법·권한은 MySQL이 판단합니다.

## 출제 전 확인

1. 저장 후 Test로 정답을 실행해 `correct`가 나오는지, 결과 표현이 지문과 같은지 확인합니다.
2. 정렬 기준을 바꾼 대체 정답, 별칭만 다른 정답, 숫자 표시만 다른 답과 실제 값이 다른 답을 Test해 공개 규약대로 판정되는지 확인합니다.
3. 다른 사람이 지문·init·정답·예시 출력을 독립적으로 검토합니다.
4. 문제 세트 전체는 [REVIEW.md](REVIEW.md)의 절차대로 `scripts/review-challenges`로 한 번에 검사할 수 있습니다. 여기 적힌 규칙 위반을 자동으로 찾아 줍니다.

## 제출 접수와 장애 처리

- Test와 Submit은 문제 공개 상태, 선수 문제, 팀 소속, 전체 시작 시각을 동일하게 검사합니다. 일시 중지 중에는 둘 다 실행하지 않습니다. Test는 기존과 같이 성적·오답 횟수를 기록하지 않습니다.
- Submit은 서버에서 접수할 때 전체 종료 시각과 문제별 마감을 검사합니다. 마감 전에 접수한 답은 채점이 늦게 끝나도 접수 시각으로 저장합니다. 전체 종료 후 보기 설정은 새 성적 제출을 허용하지 않습니다. 학생 기기 시계는 마감 안내에만 사용합니다.
- 학생 SQL의 문법·데이터·권한 오류, 명시적인 실행/결과 한도 위반과 결과 불일치는 오답입니다. 정답/init 오류, 채점 서버 장애, 통신 실패와 분류되지 않은 오류는 판정 불가이며 오답 횟수를 차감하지 않습니다. 판정 불가 시 재시도하고, 반복되면 담당자에게 문의합니다.
- Test와 Submit을 합쳐 계정(팀 모드에서는 팀)당 동시에 한 쿼리, UTC 분 구간당 최대 60개 실행 요청을 허용합니다. 이는 서버 보호를 위한 요청 제한이며 문제의 오답 허용 횟수와 별개입니다. 오답 허용 횟수·오답 분당 제한에는 저장된 오답만 포함합니다.
- 저장 실패는 완료로 표시하지 않습니다. 이 변경은 접수 후 처리 지연을 다루며, 서버 프로세스 중단에도 자동 복구되는 영속 작업 큐를 추가하지는 않습니다. 새 요청으로 다시 제출하면 그 요청의 접수 시각으로 마감을 검사합니다.
